# Pleos SDK·API 데이터 정리

공식 [Pleos Playground](https://developers.pleos.ai/playground) 개발 문서를 기준으로, 차량용 앱에서 쓸 수 있는 데이터와 기능을 정리했습니다. 설명회 영상에서 소개한 것보다 훨씬 많은 차량 데이터와 제어 기능이 제공됩니다. Vehicle SDK에는 19개 기능 도메인이 문서화되어 있고, NaviHelper SDK로 내비게이션·경로 데이터에도 접근할 수 있습니다.

기능은 세 종류로 나뉩니다. 모델별 지원 여부와 권한이 서로 다르고, 문서에 있다고 모든 차량에서 작동하지는 않습니다.

| 구분 | 의미 |
|---|---|
| 조회 (Get) | 차량의 현재 상태나 설정값을 읽음 |
| 제어 (Set) | 공조, 시트, 도어 등 일부 차량 기능의 값을 변경 |
| 이벤트 (Callback) | 차량 데이터가 바뀌면 앱이 그 변화를 전달받음 |

## 1. Vehicle SDK: 차량 데이터

공식 Vehicle SDK v2.3.2 문서 기준 (Vehicle Service v2.3.21). 문서: [Vehicle SDK API 개요](https://document.pleos.ai/api-reference/connect-sdk-pleos/Vehicle/intro)

| 도메인 | 제공 정보와 기능 |
|---|---|
| Brake | 브레이크 페달 및 주차 브레이크 상태 |
| CarInfo | 제조사, 연식, 차량 외부 치수 등 기본 정보 |
| Display | 디스플레이에 쓰는 온도 등의 표시 단위 |
| Door | 도어 개폐·잠금 상태 조회 및 제어 |
| DrivingMode | 주행 모드, 크루즈 컨트롤 관련 상태 |
| EvBattery | EV 배터리 상태, 충전 상태, 전비 |
| Fuel | 연비 등 연료 관련 정보 |
| HVAC | 실내 온도, 풍량, 습도, 공조 설정 및 제어 |
| Light | 차량 조명 상태, 앰비언트 조명 제어 |

슬랙 공유본에는 위 9개만 있어서, 나머지 10개 도메인은 공식 Vehicle SDK 소개 문서(2026-11-07 수집본)에서 보충했습니다.

| 도메인 | 제공 정보와 기능 |
|---|---|
| Odometer | 총 주행 거리, 트립 주행 거리·시간, 주행 거리 단위 조회 |
| Safety | 차량 경고(Warning) 정보 조회 |
| Seat | 좌석 위치·각도·기능 제어 및 조회 |
| SideMirror | 사이드미러 열선 상태 조회·설정 |
| Steeringwheel | 스티어링휠 상태, 열선 조회·제어 |
| Tire | 타이어 상태 조회 |
| Toll | ETCS(하이패스) 음성 안내 음량 등 조회·설정 |
| TurnSignal | 방향 지시등 상태 조회 |
| Window | 창문 제어 및 상태 조회 |
| Wiper | 와이퍼 제어 및 상태 조회 |

일부 도메인은 센서 조회를 넘어 차량 하드웨어를 제어할 수 있습니다. 예를 들어 공조 설정, 앰비언트 조명, 시트 설정을 외부 앱의 핵심 사용자 경험과 연결할 수 있습니다.

## 2. NaviHelper SDK: 내비게이션 데이터

차량의 기본 내비게이션 앱과 연동하는 SDK입니다. 문서: [NaviHelper SDK](https://document.pleos.ai/api-reference/connect-sdk-pleos/NaviHelper/intro)

| 구분 | 제공 기능 |
|---|---|
| 목적지 | 목적지 설정, 조회, 취소 |
| 경유지 | 경유지 추가, 조회, 삭제 |
| 경로 | 경로 요청, 경로 옵션 변경, 재탐색 |
| 주행 이벤트 | 경로 탐색 및 주행 상태 변화 이벤트 |
| 내비게이션 | 내비게이션 정보 조회 및 화면 표시 요청 |
| 충전 정보 | 충전 사업자 관련 정보 조회 기능 소개 |

내비게이션을 새로 만들지 않고도, 외부 서비스가 추천한 목적지나 경유지를 차량 내비게이션에 전달할 수 있다는 점이 유용합니다.

경로·주행 이벤트를 제공한다고 해서 ETA, 실시간 교통량, 개별 도로 구간 정보 같은 상세 필드까지 모두 제공되는 것은 아닙니다. 이 필드들은 API Reference에서 따로 확인해야 합니다.

## 3. 위치·음성 SDK

| SDK | 활용 가능한 데이터 및 기능 |
|---|---|
| FusedLocation | GPS, IMU 및 차량 센서 정보를 융합한 차량 위치 |
| SpeechToText | 음성 입력을 텍스트로 변환한 결과 |
| TextToSpeech | 앱에서 생성한 텍스트를 차량에서 음성으로 재생 |

FusedLocation은 차량 센서 정보로 위치 정확도와 안정성을 높이는 SDK로 소개되어 있습니다. GPS 원시 데이터나 카메라 영상 자체를 외부 앱에 공개한다는 의미는 아닙니다.

## 4. 별도로 존재하는 Vehicle Data API

Pleos에는 차량 안에서 동작하는 Vehicle SDK 외에, 차량 데이터를 외부에서 조회하는 HTTPS REST API인 Vehicle Data API가 있습니다. 문서: [Vehicle Data API](https://document.pleos.ai/api-reference/vehicle-data-api/intro)

| 엔드포인트 | 조회 데이터 |
|---|---|
| `/batteries` | 충전 여부, 배터리 잔량, 완충 예상 시간 |
| `/powertrains` | 엔진, 모터, 배터리 시스템 상태 |
| `/locations` | 위도·경도, 고도, 방향, 속도 |
| `/driving` | 시동, 누적 주행거리, 주차 상태 |
| `/status` | 도어, 트렁크, 타이어 공기압, 경고등, 공조 |
| `/powertrains/data` | 배터리 팩 전압, 엔진 RPM, 오일 온도 |
| `/speed` | 속도 관련 원천 데이터 |
| `/driving/data` | 운행 관련 원천 데이터 |
| `/status/data` | 차량 센서 관련 원천 데이터 |

**주의:** 공식 문서의 2026년 8월 안내 기준으로 Vehicle Data API는 유럽에서만 쓸 수 있습니다. 이번 한국 공모전에서 이 REST API를 쓸 수 있다고 가정하면 안 됩니다. Vehicle SDK와는 인증·동의 체계도 따로 씁니다.

## 5. 제품 개발 관점에서의 가능성

| 아이디어 | 핵심 SDK | 판단 |
|---|---|---|
| 배터리 기반 이동 계획 | EvBattery + NaviHelper | 구현 가능성 높음 |
| 차량 상태에 따른 실내 환경 자동화 | HVAC + Seat + Light | 제어 권한 검증 필요 |
| 운행·정차 맥락에 맞춘 AI 인터페이스 | Brake + STT + TTS | 안전 및 주행 중 UI 제한 확인 필요 |
| 운전 습관 분석 | Odometer + DrivingMode + Brake | 데이터 수집 빈도와 이력 제공 여부 확인 필요 |
| 차량 상태 진단 서비스 | Safety + Tire + EvBattery | 진단 코드 및 상세 필드 범위 확인 필요 |

## 아직 확인하지 못한 사항

SDK 소개 문서로 데이터 도메인과 대표 기능은 확인되지만, 아래 항목은 아직 확정할 수 없습니다.

1. 차량 속도, SOC, 브레이크 등 개별 데이터의 실제 필드명과 타입
2. 실시간 데이터 업데이트 주기와 지연 시간
3. 주행 중 앱에서 접근할 수 없는 데이터나 제어 기능
4. SDK 권한별 앱 마켓 심사 및 상용 배포 제한
5. 공모전에서 추가 제공한다는 비공개 SDK의 실제 범위

## 판단과 다음 단계

차량 상태와 사용자의 이동 맥락을 결합하는 앱에 필요한 기반은 꽤 넓게 제공됩니다. 반면 장기간 운행 이력, 카메라 원본, 세밀한 운전자 행동 데이터에 접근할 수 있는지는 아직 입증되지 않았습니다.

출품작을 설계하려면 다음 단계로 공식 API Reference의 개별 메서드를 기준으로 읽기 가능 필드, 제어 가능 필드, 권한, 이벤트 지원 여부를 분해한 데이터 사전을 만드는 것이 가장 유용합니다.
