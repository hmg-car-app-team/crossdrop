# 크로스드롭 CrossDrop 기획서 (접수양식 02장 초안)

> 팀명·대표자·연락처 등 참가자 정보는 **접수양식 01에 기재**합니다(이 문서에는 쓰지 않음).
> 이 문서의 "동작"은 **Pleos Connect 에뮬레이터, 호스트 PC의 로컬 테스트 서버, 가공 시연 데이터** 기준입니다. 실차·실제 휴대폰·운영 서버 결과가 아닙니다.
> 표기: **[기획 가정]** = 기획 원문의 가정(검증하지 않음), **[구현]** = 코드·테스트 또는 에뮬레이터 검증으로 확인, **[미구현/미검증]** = 6장 한계 참조.
> 독립 검증에서 나온 Minor 결함은 수정했고, 동의 팝업 전문 표시는 수정 빌드에서 에뮬레이터 화면으로 재확인했습니다. 나머지 수정(내비 문구·배지·개인정보 탭·만료 안내)은 단위 테스트까지 확인했고 화면 재검증은 하지 않았습니다(7장 표 참조).

## 1. 앱 한 줄 소개

아이폰·안드로이드 구분 없이, 휴대폰에서 QR 로 연 웹 페이지(앱 설치 불필요)로 **사진·PDF·음악·지도 링크를 차량 화면으로 보내고**, 사진·PDF 는 정차 중에만 보여 주며 목적지는 운전자가 수락해야 내비게이션에 요청하는 차량용 앱입니다.

## 2. 기획 배경

- **주목한 순간**: Pleos Connect 는 안드로이드(AAOS) 기반이라 아이폰 사용자는 차량으로 파일·정보를 보내기 불편합니다. 동승자가 찾은 식당 주소를 운전자가 다시 검색해 입력하거나, 작은 폰 화면을 돌려 보는 일이 흔합니다. (기획 원문의 문제 인식)
- **왜 해결이 필요한가**: 운영체제에 관계없이 "그냥 보내면 되는" 경험이 차량에는 없습니다. (기획 원문)
- **외부 입력이 들어오는 앱이라는 점**: 이 앱은 휴대폰이 보낸 파일·링크를 차량이 처리합니다. 그래서 형식 허용 목록·크기 상한·매직 바이트 검사를 서버와 차량 양쪽에서 하고, 링크는 문자열로만 해석하며(따라가지 않음), 경로는 **운전자가 수락한 뒤에만** 요청하도록 설계했습니다.
- **주행 안전 관점**: 사진·PDF·QR 은 정차 중에만 보이고, 주행 중에는 짧은 안내 패널과 음성 한 줄만 제공합니다.

| 기능 | 내용 | 상태 |
|---|---|---|
| 휴대폰 연결(QR) | 정차 중 동의 팝업 후 서버에서 1회용 코드(10분) 발급, QR 표시. 휴대폰 카메라로 열면 업로드 웹 페이지. 코드 직접 입력 경로는 없음 | [구현] QR 화면 에뮬레이터 확인, QR 을 디코더로 따로 해독해 주소 형식 확인. **실제 휴대폰 스캔은 미검증** |
| 파일 보내기 | 사진(JPG/PNG/WebP), PDF, 음악(MP3/M4A/AAC/OGG). 사진·PDF 10MiB, 음악 20MiB 상한. 영상 미지원 | [구현] 형식 검사·크기 상한은 서버 테스트와 curl 로 확인 |

| 목적지 링크 | 카카오맵·네이버지도(lat/lng 형식)·Apple 지도·구글지도의 **좌표가 들어 있는 전체 주소**만 해석. 단축 링크(kko.to, naver.me, maps.app.goo.gl)는 따라가지 않아 "열 수 없어요" | [구현] 파서 단위 테스트, 카카오·구글 링크 수신 에뮬레이터 확인 |

| 음악 | 오디오 포커스 + MediaSession. 주행 중에도 재생 유지, 조작 UI 는 정차 중에만 | [구현] 포커스 획득·MediaSession `PLAYING` 확인. **실제 소리 출력은 미검증** |
| 24시간 자동 삭제 | 기기: 받은 항목을 24시간 뒤 삭제(시작 시 + 실행 중 30초 점검). 서버: 차량이 받으면 즉시 삭제, 늦어도 24시간 | [구현] 경계값 테스트, 화면의 "24시간 후 삭제" 표시. **24시간 경과 후 실제 삭제는 미검증** |
| 개인정보·삭제 탭 | 받은 항목 모두 삭제(+서버 세션 삭제), 연결 끊기·동의 철회 | [구현] 에뮬레이터 확인 |
| 시연 모드 | 서버 없이 가상 QR·가상 수신. 화면에 `시연` 배지, 서버로 보내거나 저장하지 않음 | [구현] |

**차량 특화 요소**
- 기어·UX 제한·차속 신호로 주행/정차를 판정(신호를 모르면 주행으로 간주).
- NaviHelper `requestRoute` 로 목적지 안내 요청, TTS/STT 로 목적지 수락.
- 사진·PDF·QR·설정은 정차 시에만, 주행 중에는 읽기 전용 한 화면.

### 주행 안전 설계
- **DO 선언**: `distractionOptimized=true`.
- **주행 중**: 탭·버튼·QR·사진·PDF 없이 받은 개수·음악 상태·동기화 상태만 표시. 열람 중이던 사진/PDF 는 주행 전환 시 닫힘. 주행 중 도착 항목은 짧은 안내 패널 + TTS 한 줄. 에뮬레이터 확인: 실신호(D, 40km/h)에서 화면 요소 확인(플랫폼이 "주행 중에는 사용할 수 없습니다" 오버레이를 덮음), 주행 시뮬레이션 신호로 PDF 열람 중 즉시 닫힘 확인.
- **자동 이동 금지**: 목적지를 받자마자 이동하지 않고, 운전자 수락 후에만 요청.
- **외부 입력 최소화**: 다른 앱이 파일·링크를 던질 수 있는 공유 인텐트·서비스·리시버 선언 없음. 위치·저장소·카메라 권한 선언 없음.

## 4. 주요 사용 시나리오

**사용자**: 아이폰을 쓰는 운전자·동승자, 가족 여행객, 렌터카·공유차 이용자 (기획 원문의 타깃)

**이용 흐름 (에뮬레이터 + 로컬 서버 시연 기준, 휴대폰 역할은 curl/호스트 브라우저)**
1. 정차 중 `휴대폰 연결` 탭에서 동의 후 QR 이 표시됩니다. 휴대폰이 QR 주소의 업로드 페이지를 열어 파일·링크를 보냅니다.
2. 5초 안팎에 "사진 1개가 도착했어요" 안내가 뜨고, 정차 중 받은 항목에서 사진·PDF 를 열어 봅니다.
3. 카카오맵 전체 링크를 보내면 "강남역 — 이 목적지로 안내할까요?"가 뜨고, 수락(에뮬레이터에서는 터치)하면 내비 경로 요청이 나갑니다. 취소하면 요청하지 않습니다.
4. 주행 상태가 되면 사진·PDF 는 닫히고 읽기 전용 화면만 남습니다. 재생 중인 음악은 이어집니다.
5. 렌터카 등에서는 `받은 항목 모두 삭제` 또는 연결 끊기로 지울 수 있고, 항목은 24시간 뒤 삭제되도록 구현했습니다(경과 후 실삭제는 미검증).

## 5. 개발 계획

**개발 환경**: Pleos Connect 에뮬레이터(AAOS 기반), Kotlin, Jetpack Compose, 최소 SDK 28 / target 35. 앱 ID `com.hmgcarapp.crossdrop`. 서버는 Python 3 표준 라이브러리만 쓰는 **로컬 실행·테스트용 릴레이 서버**(`server/crossdrop/`).

**Pleos SDK 사용**

| SDK | 사용처 |
|---|---|
| Vehicle | 기어·차속(주행/정차 판정) |
| NaviHelper | 목적지 안내 요청(`requestRoute`) |
| TextToSpeech / SpeechToText | 도착 안내, 목적지 질문과 수락 응답 1회 청취 |

Pleos 디자인시스템 컴포넌트를 사용합니다. QR 표시·이미지/PDF 뷰어·상단 배너·빈 상태 컴포넌트가 없어 `Canvas`·`Image`·`PleosPanel` 등으로 최소 대체했습니다.

**전송 방식**: 클라우드 릴레이(원문 1안) 방식으로, 차량이 1회용 코드(QR)를 받고 휴대폰이 업로드한 파일을 차량이 받아 간 뒤 서버 사본을 삭제합니다. 서버는 파일을 **암호화해 전달하지 않습니다**(원문 표현과 다름, 아래 표 참조).

**원문 기획 대비 달라진 점**

| 원문 기획 | 구현 결과 |
|---|---|
| 클라우드 릴레이, 파일 암호화 전달 | 릴레이 서버를 직접 구현했으나 **로컬 실행·테스트 전용**(루프백 바인딩만, TLS·사용자/앱 인증 없음). 종단 간 암호화 없음. release 앱은 서버 주소가 비어 있어 서버와 통신하지 않고 시연 모드만 동작. 운영 서버 구축은 포함하지 않음 |
| 로컬 전송(핫스팟, 2안) | 근거 불확실해 **미구현** |
| iOS·안드로이드 컴패니언 앱, 공유 시트 연동 | **범위 밖**. 웹 업로드로 대체. 외부 앱이 직접 입력을 넣는 경로를 만들지 않기 위해 안드로이드 공유 연동도 하지 않음 |
| 스마트폰 연결 도우미(블루투스·프로젝션 진단) | SDK 가 없어 **제외**, 정적 안내 패널로 대체 |
| 지도 앱에서 공유한 링크를 바로 목적지로 | 앱 공유 링크 대부분이 단축 주소라 따라가지 않는 정책상 해석 불가. **좌표가 들어 있는 전체 주소 링크만** 지원 |
| 사진·영상 보기, 문서, 음악 | **영상 미지원**. 사진·PDF 는 정차 중만. 음악 스트리밍 링크 미지원, 음악 파일만 |
| 사진 슬라이드 자동 재생 | 목록에서 열어 보는 방식(슬라이드쇼 미구현) |
| 차속 기반 제한 | 기어 + UX 제한 + 차속, 신호를 모르면 주행으로 간주 |
| 받은 파일 24시간 후 자동 삭제 | 구현. 단, 앱이 실행 중일 때 점검(백그라운드 서비스 없음). 경과 후 실삭제는 미검증 |
| 다중 기기 동시 공유(3단계) | **미구현**. 서버의 1회용 코드는 한 번만 사용(claim)할 수 있어 한 차량 연결에 휴대폰 1대만 연결됨. 여러 명이 보내려면 새 QR 을 만들어야 함(향후 과제) |
| 정차(P단) 시 사진·문서 자동 열림/자동 재생 | **미구현**. 정차해도 자동으로 열리지 않고 운전자·동승자가 받은 항목 목록에서 직접 연다(주행 중 오작동 방지를 위한 안전 측 변경) |
| 반납 시점 삭제 안내 표시 | **미구현**. 반납 전용 안내는 없고, 항목별 `N시간 후 삭제` 표시와 `받은 항목 모두 삭제`·연결 끊기 버튼으로 대체 |
| 시동과 함께 상시 수신 | 폴링은 **앱이 켜져 있을 때만**. 꺼져 있으면 다음 실행 때 확인 |

## 6. 기대효과 및 발전 가능성

- **사용자 가치**: 운영체제와 무관하게 휴대폰의 목적지·사진·문서·음악을 차량으로 옮기는 번거로움을 줄이는 것을 목표로 합니다. 실제 효과는 실차·실사용자로 측정한 바 없으며, 이 문서는 효과 수치를 주장하지 않습니다.
- **타깃 고객**: 아이폰 사용자, 가족·동승 이동이 많은 사용자, 렌터카·공유차 이용자 (기획 원문).
- **예상 지표 [기획 가정]**: Pleos Connect 적용 10만 대 x 설치율 25% 가정 시 MAU 약 1.8만 명, 30일 리텐션 35% 목표. 근거 자료가 없는 가정이며 구현·측정 결과가 아닙니다.
- **발전 방향 (미구현)**: 운영 가능한 서버(TLS, 앱 무결성 증명, 악성 파일 스캔, 신고·차단), iOS 공유 시트·컴패니언 앱, 서버 측 단축 링크 해석(별도 위험 검토 선행), 렌터카·카셰어링 제휴, 뒷좌석 디스플레이 확장 (기획 원문의 확대 계획 중).

### 알려진 한계 (정직한 고지)
- **환경상 미검증**: 내비 **실제 안내 시작**(요청 호출·내비 화면 표시까지만), Portrait 실화면(Landscape 만 확인), **24시간 경과 후 실제 삭제**, **실제 소리 출력**, **QR 실제 휴대폰 스캔**, **실제 음성 인식(STT)**, PDF 다중 쪽 이동, 아이폰 HEIC(허용 목록에 없음).
- **서버는 로컬 테스트 서버 기준**: 인증·TLS 없음, 루프백 바인딩만, 에뮬레이터는 `10.0.2.2` 평문 HTTP(debug 빌드 한정). 실서비스에는 TLS, 앱 무결성 증명, 악성 파일 스캔, 신고·차단이 필요. 부하·DoS 내성은 시험하지 않음.
- **서버 보관**: 파일은 서버에 최대 24시간 보관되며 운영자가 볼 수 있음. 서버가 계속 떠 있는 동안에만 24시간 삭제가 보장되고, 강제 종료 시 임시 파일이 남을 수 있음.
- **PDF 활성 콘텐츠 검사는 최선 노력**: `/JavaScript`·`/OpenAction`·`/Launch` 등 알려진 키워드만 걸러내며 스트림 안쪽은 검사하지 않아 **우회될 수 있음**(예: 문자열·주석 안에 가짜 stream 표식). 실제 방어는 허용 목록과 Android `PdfRenderer` 가 PDF JavaScript 를 실행하지 않는다는 점에 의존하며, 후자는 문서 기준이고 실기 미확인. 이미지·PDF 디코더 자체의 취약점은 막지 못함.
- 폴링은 앱 실행 중에만(백그라운드 서비스 없음). 음악은 MediaBrowserService 가 없어 차량 미디어 화면에 노출되지 않고 앱이 종료되면 재생도 끝남(미디어 앱 규정 준수를 주장하지 않음). 시연 음악은 WAV 를 M4A 이름으로 저장한 시연 전용 파일.
- 시계가 동기화되기 전 콜드 부팅에서는 항목이 한꺼번에 삭제될 수 있음(프라이버시 우선). 기기 내 저장 데이터는 연결 토큰만 암호화(Keystore)하고 나머지(받은 항목 메타데이터·파일)는 평문이다.
- **release APK 는 시연 모드만 동작**: release 빌드는 서버 주소가 비어 있어 서버와 통신하지 않는다(`apps/cross-drop/build.gradle.kts`). 심사용 APK 만 설치하면 휴대폰→차량 실제 전송은 체험할 수 없다. 실제 전송은 로컬 서버를 실행(`server/crossdrop/README.md` 절차)한 debug 빌드로 확인하거나, 접수양식 7번의 시연 영상으로 볼 수 있다.
- **연결 토큰 저장**: 토큰은 Android Keystore AES-GCM 으로 암호화해 저장한다. 키를 쓸 수 없으면(키 소실·손상) 연결을 버리고 다시 연결하게 한다. 연결 코드·만료 시각은 평문이며 연결을 끊으면 삭제된다. 에뮬레이터·실기 Keystore 동작은 아직 검증하지 않았다.
- 단축 링크 불가, 네이버지도는 `lat/lng` 형식만 지원.
- 권한 대화상자(CAR_SPEED)는 정차 상태에서 허용해야 함.
- 주행 중 실신호 상태에서는 플랫폼이 앱 위에 "주행 중에는 사용할 수 없습니다"를 덮으므로, 주행 화면의 시각 증거는 시뮬레이션 신호로 촬영함(파일명 `SIM`).
