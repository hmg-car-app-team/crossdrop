# 크로스드롭 CrossDrop

아이폰, 안드로이드 구분 없이 사진, 음악, 문서, 목적지를 차량 화면으로 한 번에 보낼 수 있는 기기 간 공유 앱입니다.

> 현대자동차그룹 차량용 앱 개발 공모전 출품작. Pleos Connect(Android Automotive) 환경용 Android 앱입니다.

## 핵심 기능

- **휴대폰 연결(QR)**: 정차 중 `휴대폰 연결` 탭 → 동의 팝업 → 릴레이 서버에서 1회용 코드(10분)를 받아 QR 표시(코드를 직접 입력하는 대체 경로는 없다; 새 QR 은 연결된 뒤에도 만들 수 있다). 휴대폰 기본 카메라로 스캔하면 업로드 웹 페이지(`/u#코드`)가 열리고, 파일(사진 JPG/PNG/WebP, PDF, 음악 MP3/M4A/AAC/OGG)이나 지도 링크를 보낼 수 있다. 차량은 5초마다 새 항목을 확인한다(앱이 켜져 있을 때만). 화면 위쪽에 연결 단계(1 서버 확인 → 2 QR 표시 → 3 폰 연결 대기 → 4 연결됨)가 표시되고, 실패한 단계는 실패로 표시된다(기존 상태를 조합할 뿐 서버 변경 없음).
- **받은 항목(정차)**: 목록(최신순)에서 사진·PDF 는 열람(PDF 는 쪽 이동), 음악은 재생/일시정지/정지, 목적지는 안내 확인. 항목마다 `N시간 후 삭제` 표시. 항목이 있으면 ‘공유차·렌터카를 반납하기 전에 받은 항목을 모두 삭제하세요.’ 안내와 `받은 항목 모두 삭제` 버튼이 함께 보인다(정차 중에만 조작).
- **새 항목 알림(주행 중 포함)**: 상단 짧은 안내 패널 + TTS 한 줄("사진 1개가 도착했어요. 정차 후 확인하세요."). 사진·PDF 는 주행 중 열 수 없다.
- **목적지 링크 → 길 안내**: 카카오맵(`/link/map|to/이름,위도,경도`), 네이버지도(`?lat=&lng=`), Apple 지도(`?ll=`·`coordinate=`·`daddr=`), 구글지도(`@위도,경도`·`!3d!4d`·`q=|query=|ll=|destination=`) 링크의 **문자열만** 해석한다. 단축 링크(kko.to·naver.me·maps.app.goo.gl·goo.gl)와 좌표가 없는 링크는 "열 수 없어요" 로 안내(따라가서 확인하지 않음). 목적지가 도착하면 TTS 가 "강남역을 목적지로 안내할까요?" 하고 질문 **직후 한 번만** 음성 인식("응/네" 수락, "아니" 거절). 정차 중에는 터치("안내 시작")로도 선택한다. 수락해야만 NaviHelper `requestRoute` 를 호출한다. 받자마자 자동 이동하지 않는다.
- **음악**: 오디오 포커스 + MediaSession(하드웨어 미디어 키). 주행 중에도 재생은 이어지지만 조작 UI 는 정차 중에만 나온다. 영상은 재생하지 않는다.
- **24시간 자동 삭제**: 받은 항목·파일은 이 기기에서 24시간 뒤(앱 실행 중 30초마다 점검, 시작할 때도) 삭제, 서버는 항목을 받는 즉시 지우고 늦어도 24시간 뒤 삭제. `개인정보·삭제` 탭: 받은 항목 모두 삭제(+서버 세션 삭제 요청), 서버 연결 끊기·동의 철회.
- **시연 모드**: 서버 없이 가상 QR·가상 수신·목적지 음성 수락·사진/PDF 열람·24시간 삭제를 보여 준다. 화면에 `시연` 배지. 시연 데이터는 서버로 가지 않고 저장하지 않는다(앱 시작 시 정리).
- **화면**: Pleos 컴포넌트·토큰만 사용. 주행 중에는 조작 없는 한 화면(받은 개수·음악 상태·동기화 상태). 정차 시 3탭(받은 항목/휴대폰 연결/개인정보·삭제). Landscape/Portrait 모두 단일 열.

## 실행 방법

필요한 것: JDK 17, Android SDK(compileSdk 35). 디자인시스템·`:core`·SDK 의존성이 이 저장소에 포함되어 있어 `app/` 만으로 단독 빌드됩니다. (Pleos SDK 는 공개 Maven 저장소 `nexus-playground.pleos.ai` 에서 받으므로 빌드 시 인터넷이 필요합니다.)

```bash
export JAVA_HOME=<JDK 17 설치 경로>
export ANDROID_HOME=<Android SDK 경로>      # 또는 app/local.properties 에 sdk.dir=<Android SDK 경로>
cd app
./gradlew :cross-drop:assembleDebug              # 디버그 APK: cross-drop/build/outputs/apk/debug/
./gradlew :cross-drop:assembleRelease            # 릴리스 APK: cross-drop/build/outputs/apk/release/
```

`local.properties` 는 개인 환경 파일이라 저장소에 포함하지 않습니다(`.gitignore` 로 제외). 환경변수 `ANDROID_HOME` 을 쓰면 만들 필요가 없습니다.

## 테스트 실행

```bash
cd app
./gradlew :core:test :cross-drop:testDebugUnitTest
```

JVM 단위 테스트이며 에뮬레이터가 필요 없습니다. 결과 리포트는 `*/build/reports/tests/` 에 생성됩니다.

## 에뮬레이터 설정

Pleos Connect 에뮬레이터(Android Automotive 기반)에서 동작을 확인합니다. 설치 방법과 Virtual Console 사용법은 [에뮬레이터 가이드](docs/guide/03-emulator-setup.md)를 따릅니다. 첫 실행 시 Pleos 차량 정보 권한 대화상자가 뜨면 허용해야 합니다.

테스트 환경 메모: 개발과 검증은 아래 환경에서 했고 실차에서는 검증하지 않았다.
- Pleos Connect 에뮬레이터: Pleos Connect v2.1.0 (AVD 이름 pleos21)
- Android: 14 (API 34, Android Automotive 기반 Pleos Connect 시스템 이미지)
- 화면 규격: 2560x1440, 160dpi(AVD 설정 기준, 기기 이름 Pleos_Connect_v2_0), 가로(Landscape). 세로 화면은 확인하지 못했다(미확인)
- 사용자: 10 (운전자 프로필)
- 빌드 환경: JDK 17, compileSdk 35 / targetSdk 35 / minSdk 28
- 검증 방법: Pleos Connect 에뮬레이터 + Virtual Console(기어·속도 주입), 로컬 서버(휴대폰 역할은 curl), debug 빌드의 adb 시연 주입, JVM 단위 테스트
- 실차: 미검증
- 에뮬레이터 실행 파일·Android Studio 의 정확한 빌드 번호: 미확인

## 데이터 출처

| 항목 | 출처 |
|---|---|
| 사진·PDF·음악·지도 링크 | 사용자가 휴대폰 웹 업로드 페이지(QR 로 열림)에서 직접 보낸 것. 로컬 테스트용 릴레이 서버(`server/crossdrop/`, 운영·배포하지 않음)를 거친다. release APK 는 기본 `http://127.0.0.1:8780`(호스트 서버 + `adb reverse`)로 동의 후에만 통신하고, 서버가 없으면 통신하지 않으며 시연 모드(가상 QR·가상 수신)로 볼 수 있다 |
| 목적지 | 카카오맵·네이버지도·Apple 지도·구글지도 링크의 **문자열만** 해석한 장소 이름·좌표(링크를 따라가거나 외부 지도 API 를 호출하지 않음) |
| 기어·정차 판정 | Pleos Vehicle SDK / 차량 속성(core) |
| 경로 요청·음성 | Pleos NaviHelper `requestRoute`(사용자가 수락한 뒤에만), Pleos TTS/STT |
| 시연 자료 | 앱에 내장한 가상 데이터(서버로 보내지 않고 저장하지 않음) |

## 개인정보 처리

- **서버 운영자는 보관 시간 동안 업로드 파일을 볼 수 있고 종단 간 암호화가 없다.** 서버는 항목을 차량이 받으면 즉시 삭제하고 늦어도 24시간 뒤 삭제한다. 휴대폰 업로드 페이지에도 이 고지('운영자가 파일을 열람할 수 있음·민감한 파일은 보내지 말 것')와 삭제 시점 안내가 표시된다.
- **기기에 저장**: 받은 사진·PDF·음악(앱 전용 저장소, 원래 파일명 미저장)과 목적지(이름·좌표)는 24시간 뒤 삭제. 연결 토큰은 Android Keystore 로 암호화해 저장하며 연결을 끊으면 지운다. 동의 철회는 이미 받은 항목을 지우지 않으므로 `받은 항목 모두 삭제`를 따로 쓴다.
- **보내지 않는 것**: 이름·계정·기기 번호·위치. 위치·저장소·카메라·연락처 권한을 선언하지 않으며 로그에 URL·좌표·파일명·코드·토큰을 남기지 않는다. 동의는 기본 꺼짐이다.
- 서버는 인증·TLS 가 없는 로컬 테스트용이며 법률 검토는 하지 않았다.

## 알려진 한계

- **서버 주소·동의·페어링 토큰**: 동의와 페어링 토큰은 서버 주소와 무관하게 저장된다(저장 형식은 바꾸지 않음). 서버 주소가 다른 빌드로 바뀌어도 기존 동의·토큰이 유지될 수 있으니, 주소를 바꾼 뒤에는 '서버 연결 끊고 동의 철회' 후 다시 연결하자. 앱은 동의 안내에 현재 전송 대상 호스트:포트를 표시한다.
- **평문 loopback**: 전송은 `http://127.0.0.1` 평문이라 같은 기기의 포트 선점 프로세스를 가려내지 못한다(개발·시연용 한계).
- **`adb reverse` 는 기기 재부팅·USB 재연결 시 풀린다.** 그때는 명령을 다시 실행해야 한다(연속 5회 실패 뒤 재시도는 60초 간격).
- **release QR 은 실제 폰에서 열리지 않는다**: QR 에 든 주소가 `127.0.0.1` 이라 폰으로 스캔해도 폰 자신의 루프백을 가리킨다. 호스트 PC 의 브라우저/curl 로만 시연할 수 있고, 폰 접속에는 https 서버 주소가 필요하다.
- 재리뷰 조치: 연결 해제·전체 삭제처럼 연결 정보가 없는 상태가 저장되면 봉인 캐시(마지막 평문·암호문 쌍)를 비워, 해제된 토큰의 평문이 이후 봉인 실패 때 재사용되지 않고 메모리에도 남지 않는다. 봉인 실패 콜백도 다른 스레드에서 보이도록 했다. 이미 해제 전에 프로세스 메모리에 있던 값은 가비지 컬렉션 전까지 남을 수 있다.
- **검증 후속(2026-11-11)**: ① 동의 철회(서버 연결 끊기)는 이미 받은 항목을 지우지 않는다(팝업이 '받은 항목은 그대로예요' 로 고지; 삭제는 '받은 항목 모두 삭제'). ② 연결 토큰은 Android Keystore(AES-256-GCM, 형식 `enc:v1:`)로 암호화해 저장한다(연결 코드·만료 시각은 평문 JSON, 앱 전용 저장소, allowBackup=false). 복호화에 실패하면(키 소실 등) 연결 정보만 버리고 '연결을 다시 해주세요' 로 돌아가며 받은 항목·설정은 유지한다. 암호화 저장이 실패하면 평문으로 쓰지 않고 연결 정보를 저장하지 않으며 안내를 띄운다. 구형식(평문) 값은 읽은 뒤 다음 저장 때 암호화 형식으로 바뀐다. 봉인에 일시적으로 실패해도 직전에 저장·복원한 것과 같은 토큰이면 기존 암호문을 그대로 다시 쓴다(새 암호화 없음·평문 저장 없음; 토큰이 바뀌었으면 연결 정보만 빠짐). 실패 안내는 앱 실행(컨트롤러)당 한 번만 띄운다. 남은 한계: 무효화됐지만 남아 있는 키는 스스로 복구하지 않고 연결을 다시 해야 하며, 컨트롤러 `release()` 가 전역 훅(`StateCodec.sealer` 등)을 해제하지 않고, 키가 캐시에 있으면 메인 스레드에서 `Cipher.init/doFinal` 을 호출하며, 킬 스위치는 상수라 시험이 상수 단언에 그친다. 에뮬레이터에서는 연결 토큰이 `enc:v1:` 형식으로 저장되고 평문이 파일에 없는 것, 변조 시 연결 정보만 버리고 받은 항목은 유지되는 것, 구형식 평문의 이전을 확인했다. 실기(하드웨어 보안 모듈 기반) Keystore 동작은 확인하지 못했다. ③ 서버가 꺼진 동안 연결 배지는 '연결 상태를 확인하지 못했어요' 로 바뀌지만, 서버 복구 직후 세션이 사라졌다면 다음 폴링(최대 몇 초)이 401 을 받을 때까지는 '휴대폰 연결됨' 이 남을 수 있다. ④ 미사용 QR 이 만료돼 세션이 서버에서 사라지면 앱이 연결 정보를 지우고 '연결 안 됨' 으로 돌아가며, 이때 토스트('QR 이 만료됐어요')와 함께 연결 화면의 '2 QR 만료' 단계 표시와 한 줄 안내를 새 QR 만들기·시연 시작·연결 끊기 전까지 유지한다(기존 실패 안내 pairError 와 같은 방식). ⑤ 내비 경로 요청 뒤 내비의 성공 이벤트를 받지 못하면 앱은 실패로 단정하지 않고 '안내 시작을 확인하지 못했어요' 로 안내한다(에뮬레이터 내비는 이벤트를 주지 않음).
- **에뮬레이터에서 확인한 범위와 못 한 것**: 에뮬레이터에서 설치·QR 표시(디코딩해 주소 형식 확인)·1회용 코드와 만료·사진/PDF 열람·음악 재생(MediaSession, 포커스)·링크 수락 뒤 내비 경로 요청·주행 중 읽기 전용 화면·프로세스 종료 뒤 복원·서버 중단/복구·가짜 파일 거부를 실행해 확인했다(로컬 서버와 휴대폰 역할의 curl 사용). 확인하지 못한 것: 실제 휴대폰 카메라의 QR 스캔, 실제 소리 출력, 음성 인식(STT) 수락, 여러 쪽 PDF 의 쪽 이동, 24시간 자동 삭제의 실시간 경과, 세로 화면, 실차.
- **내비 경로 안내는 에뮬레이터에서 끝까지 확인하지 못했다**: `안내 시작` 을 누르면 `requestRoute` 가 호출되고 내비 앱이 경로 후보를 띄우는 데까지 확인했지만, 완료 이벤트가 오지 않아 앱에는 확인하지 못했다는 안내가 표시된다. **STT 결과도 에뮬레이터에서는 오지 않아** 음성 수락은 시간 초과가 되고 정차 중 터치 또는 `adb` 주입(`--es heard 응`)으로 확인한다.
- **단축 링크 불가**: 카카오·네이버·구글 앱의 공유 링크는 대부분 `kko.to`·`naver.me`·`maps.app.goo.gl` 단축 주소라 따라가지 않는 정책상 해석할 수 없다. 전체 주소(좌표 포함) 링크만 목적지가 된다. 네이버지도는 `lat/lng` 쿼리 형식만 지원(일반 장소 공유 링크는 좌표가 없어 불가).
- **휴대폰 업로드 페이지에는 '운영자가 파일을 열람할 수 있음·종단 간 암호화 아님' 고지와 삭제 시점 안내가 있다**(호스트 브라우저로 확인; 480px 폭에서 오른쪽 글자 일부가 잘려 보임).
- **서버는 로컬 테스트용**(TLS·인증 없음). 실서비스에는 TLS, 앱 무결성 증명, 악성 파일 스캔, 신고·차단이 필요하다. 서버 운영자는 보관 시간 동안 파일을 볼 수 있다(종단 간 암호화 없음).
- PDF 검사는 알려진 활성 콘텐츠 키워드(`/JavaScript`·`/JS`·`/OpenAction`·`/Launch` 등)를 거르는 **최선 노력** 검사다. 스트림(압축 여부 무관, 평문 `/Type/ObjStm` 포함) 안쪽은 검사하지 않으며 우회될 수 있다. 예: 문자열·주석 안에 `>>\nstream\n` 을 넣으면 그 뒤 구간이 스트림으로 취급돼 검사되지 않는다(알려진 우회, 토크나이저 미구현). 실제 방어는 ① 허용 목록의 파일 형식만 디코더에 도달한다는 점 ② Android `PdfRenderer`(PDFium 기반)가 PDF JavaScript 를 실행하지 않는다는 점에 의존한다(근거는 문서 기준, 실기 미확인).
- 휴대폰이 보낸 파일을 차량이 열 때의 위험: 형식 허용 목록·매직 바이트·크기 검사와 PDF 활성 콘텐츠 키워드 최선 노력 검사를 하지만 이미지 디코더·`PdfRenderer` 자체의 취약점은 막지 못한다. 모르는 사람이 보낸 파일을 열지 말라는 안내를 개인정보 탭에 둔다.
- 폴링은 앱이 켜져 있을 때만(백그라운드 서비스 없음). 앱이 꺼지면 새 항목은 다음 실행 때 확인한다. 24시간 삭제도 앱이 실행될 때 점검한다(시작 시 정리 + 실행 중 30초 주기). 기기 시계를 되감으면 보관 기간이 늘어나지만 1시간을 넘는 미래 시각은 삭제한다.
- 음악은 MediaBrowserService 가 아니라 차량 미디어 템플릿/앨범 화면에 노출되지 않고, 포그라운드 서비스가 없어 앱이 종료되면 재생도 끝난다. 시연 음악은 WAV 사인파를 M4A 이름으로 저장한 것(검증 경로 우회, 시연 전용).
- 이미 서버 삭제 요청이 실패한 항목은 재시작 뒤 다시 받을 수 있다(메모리 기록뿐). 24시간 판정은 벽시계 단일 기준이라 **시계가 동기화되기 전 콜드 부팅에서는 항목이 한꺼번에 삭제될 수 있다**(프라이버시 우선). **아이폰 HEIC 는 허용 목록에 없다**(실기 확인 전).
- 시연 중에 수락한 가상 목적지도 실제 `requestRoute` 로 전달된다(오퍼 패널에 `시연 목적지` 표시).
- **iOS Share Extension·컴패니언 앱은 범위 밖**(웹 업로드로 대체). 안드로이드 공유 시트 연동도 하지 않았다(외부 앱이 직접 입력을 넣는 경로를 만들지 않기 위해). 정차 중 자동 열림·슬라이드쇼도 범위·안전 판단으로 구현하지 않았다. **스마트폰 연결 도우미(블루투스·프로젝션 진단)는 쓸 수 있는 SDK 가 없어 제외**하고 정적 안내 패널로 대체했다.
- 디자인시스템에 QR·이미지/PDF 뷰어·상단 배너·빈 상태 컴포넌트가 없어 `Canvas`·`Image`·`PleosPanel`/글줄로 최소 대체했다(`docs/apps/cross-drop.md` 기록).
